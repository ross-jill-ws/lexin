# 01 — Walking skeleton: materials table shows the first page

## Comments

**Implemented (agent, ticket 01).** All 15 criteria met. `pnpm test`: 8 tests pass (backend 4 against `lexin_test`, frontend 4). `pnpm typecheck`, `pnpm build` and `pnpm lint` are clean.

What was built:
- **Monorepo:** pnpm workspaces with `apps/backend`, `apps/frontend` and `packages/shared`, plus root `tsconfig.base.json`, Biome 2 and a `.gitignore` (node_modules, dist, build, `.env`, tsbuildinfo). `packages/shared` exports its TypeScript source (`exports: ./src/index.ts`), so it needs no build step. Vite and tsx consume it directly, and the backend's tsup bundle inlines it (`noExternal`).
- **Infrastructure:** `docker-compose.yml` runs Postgres 17-alpine on 5433 with a named volume `pgdata`. The healthcheck waits until `lexin_test` exists. `docker/init-db.sql` creates `lexin_test`, and `POSTGRES_DB` creates `lexin`. `db:up` = `docker compose up -d --wait`.
- **Env:** `apps/backend/.env.example` (copy it to `apps/backend/.env`). `src/env.ts` validates `DATABASE_URL`, `TEST_DATABASE_URL`, `PORT` and `NODE_ENV` with Zod. On bad input it prints a list of the issues and exits with code 1, without a stack trace. When `NODE_ENV=test`, which Vitest sets, it uses the test database URL.
- **Schema and migration:** `src/db/schema.ts` reuses the shared enum tuples for the pg enums. The single migration is `drizzle/0000_init.sql`. It was generated by drizzle-kit and then hand-prefixed with `CREATE EXTENSION IF NOT EXISTS pg_trgm`. It creates all the indexes from the spec. The updated-at sort index is `(updated_at DESC NULLS FIRST, id DESC NULLS FIRST)` so it matches the default `ORDER BY ... DESC`. `db:generate` reports no drift, and `db:migrate` was verified on a brand-new database.
- **API:** `createApp(db?)` in `app.ts` wires `routes/materials.ts` (a thin route) to `repositories/materials-repository.ts`, which holds all the SQL. It also sets the JSON `notFound` and `onError` handlers from `errors.ts`, which return a generic 500 message and log the error on the server. For now the route always calls the repository with `{ page: 1, pageSize: 25 }`, and ticket 03 adds the query schema and validator.
- **Frontend:** a React Router 7 SPA in data/library mode (`createBrowserRouter`; tests use `createMemoryRouter` over the same `routes`), with Mantine 9 and TanStack Query 5. TanStack Table 8 is used headlessly with manual sorting and pagination, and rows render in a Mantine `Table`. The components are `MaterialsPage`, `MaterialsTable`, `columns.tsx`, `StatusBadge` and `format.ts` (AUD currency, en-AU date, "1000 · Brisbane", enum labels). `api/client.ts` parses responses with the shared schemas and throws a typed `ApiRequestError`. The Vite dev and preview servers proxy `/api` to 3001.
- **Harnesses:** in the backend, a Vitest `globalSetup` migrates `lexin_test` once per run, `setup.ts` truncates with `RESTART IDENTITY` before each test, `test/fixtures.ts` provides the inserts, and files run serially. In the frontend, `test/render.tsx` (`renderAt(url)`) renders the page with RTL and a fresh no-retry QueryClient, and MSW (`test/server.ts`) fakes the network, failing on unhandled requests.
- **Placeholder seed:** `pnpm db:seed` loads 2 plants, 3 manufacturers and 5 materials. Ticket 02 replaces it.

Deviations and notes:
- Pinned **React Router ^7** (latest is 8) and **TanStack Table ^8** (latest is 9, which has a different API). Other packages are on their latest versions: Zod 4, Hono 4, Drizzle 0.45, Vite 8, Vitest 5, MSW 3, TypeScript 7. MSW 3 renames `onUnhandledRequest` to `onUnhandledFrame`.
- The env file lives in `apps/backend/` rather than the repo root, because every backend script runs with that working directory.
- The table renders every spec column, formatted (stories 1–7), plus the total count ("N materials"), because no later ticket owns this.
- Biome 2.6 also formats Markdown. One early `biome check --write` run reformatted `.scratch/material-register/spec.md` cosmetically (list and emphasis markers, whitespace), with no content change. `biome.json` now excludes `**/*.md`.
- On this machine port 5173 is already taken by another app, so `pnpm dev` fell back to 5180. The proxy was verified end to end there. `strictPort` is deliberately left off.
